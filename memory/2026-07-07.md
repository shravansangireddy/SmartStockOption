### Problem
- `addedPrice` was often null when adding items from the scanner (only some sources send `underlyingPrice`)
- `currentPrice` was only computed on GET — not persisted in DB
- P/L showed '—' when `addedPrice` was null, even though underlying price data was available
- `pnl` calculation used only `addedPrice` as the base — no fallback to `underlyingPrice`

### Server Fix (POST /api/watchlist)
- Made the endpoint `async` to fetch live price when `addedPrice` is missing
- Priority: `addedPrice` → `underlyingPrice` → fetch live quote
- Returns enriched data with `currentPrice` and computed `pnl` for all items

### Client Fix (WatchlistDetail.jsx)
- `pnlDollar` now falls back: `(currentPrice - addedPrice)` → `(currentPrice - underlyingPrice)` → null
- `pnlPct` computed the same way with fallback
- Added price display shows `addedPrice ?? underlyingPrice` instead of just `addedPrice`
- Header P/L uses computed `pnlPct` instead of server `w.pnl` for consistency
- Fixed JSX syntax: `)}}` → `)}` closing

### Tested
- No price: addedPrice=311.97 (fetched live), currentPrice=311.97, pnl=0
- With underlyingPrice: addedPrice=749.50, currentPrice=747.59, pnl=-0.25%

## 19:49 - DTE Added to Options & Watchlist

### Problem
- Trade setups from Section C (full analysis) didn't include `dte` — only had `expiration` as a date string
- ScannerPage and SetupCards already passed `dte` from the options chain, but Section C setups didn't
- TradeModal showed DTE in a small grid cell but no prominent badge
- Analysis setups table had no DTE column

### Backend Fix (`full-analysis.js`)
- Added `dte` field to all 5 setup types:
  - Bull Call Spread: uses `chain.dte`
  - Bear Put Spread: uses `chain.dte`
  - Long Call: uses `chain.dte`
  - Long Put: uses `chain.dte`
  - LEAPS Call: computes DTE from expiry date string (since it uses a different expiry than the chain's selected expiry)

### Frontend Fix (`TradeModal.jsx`)
- Added DTE badge in header next to Call/Put + Strike badge
- Color-coded DTE: 🔴 red for ≤7d, 🟠 orange for ≤14d, default for >14d
- Shows expiration date next to DTE badge
- DTE detail cell also color-coded with same scheme

### Frontend Fix (`AnalysisPage.jsx`)
- Added DTE column to setups table (between Expiry and Strike)
- DTE values color-coded: red ≤7d, orange ≤14d
- Falls back to `c.dte` (chain-level DTE) if setup doesn't have its own
